## 1. 게이트 판정 — 24GB 로 가능한가

Roadmap Section 0 이 이번 측정에 걸어 둔 질문이다. 실패하면 이후 계획을 경량 adaptation 으로 축소해야 했다.

| 항목 | 판정 | 근거 |
|---|---|---|
| OpenVLA 7B LoRA 1사이클이 RTX 4090 24GB 에서 가능한가 | **통과** | 2,000 스텝(8.5 epoch) 완주. VRAM 피크 18,470MiB / 24,564MiB (methodology §2.1) |

### 1.1 24GB 가 하한을 어떻게 넘겼는가

upstream 이 제시하는 LoRA 파인튜닝 메모리는 배치 16 에서 약 72GB, 배치를 줄여도 **약 27GB** 다. 24GB 는 그 하한보다 작다.

바닥을 만드는 것은 옵티마이저나 활성값이 아니라 **frozen base 가중치 15GB**(7B x bf16 2바이트)다. LoRA 가 줄이는 것은 학습 대상(어댑터 수십 MB + 그 옵티마이저 상태 수백 MB)이지 base 가 아니며, 얼려 둔 가중치도 순전파에 쓰이므로 GPU 에 올라가 있어야 한다.

넘긴 방법은 `batch_size 1` + `grad_accumulation_steps 16` 이다. 활성값은 배치에 비례하므로 배치를 1 로 내려 줄이고, 그래디언트를 16회 누적해 **유효 배치 16 을 유지**했다. 결과가 18.5GB 이고 6GB 가 남았다.

즉 27GB 라는 숫자는 특정 배치 조합에서의 값이고, 조합을 바꾸면 24GB 안에 들어온다.

### 1.2 남은 여유 6GB 를 쓰지 않았다

`batch_size 2 / grad_accumulation_steps 8` 로 바꾸면 유효 배치를 유지하면서 두 곳이 동시에 줄어든다 — gradient step 당 micro-batch 가 16회에서 8회로, **그리고 체크포인트 저장 반복도 16회에서 8회로**(§2.2). 시도하지 않았고 미확인으로 남는다.

## 2. 시간과 비용의 구조

### 2.1 예측이 맞았다

| 시점 | 스텝당 시간 | 출처 |
|---|---|---|
| probe (20스텝) | 2.67초 | methodology §2.1 |
| 본 사이클 (2,000스텝) | 2.51-2.58초 | methodology §4.2 |

차이가 6% 다. 20스텝 / 2분 30초짜리 사전 측정으로 2시간짜리 실행의 시간과 비용을 역산할 수 있다는 뜻이고, **"기본값으로 일단 걸어 보고 언제 끝나는지 지켜보는" 방식과의 차이가 여기서 갈린다.** 스크립트 기본값 `max_steps=200,000` 을 그대로 썼다면 2.53초 x 20만 = 약 140시간, $105 다.

### 2.2 비용의 23% 는 학습이 아니다

| 구간 | 시간 | 비중 |
|---|---|---|
| 학습 2,000 스텝 | 약 84분 | 89% |
| 스텝 1000 체크포인트 저장 | 약 7분 | 7% |
| 스텝 2000 체크포인트 저장 | 약 30초 | 1% |
| 모델 로딩 등 | 약 3분 | 3% |
| **총계** | **94.3분 / $1.18** | |

저장이 비싼 이유는 두 겹이다. 한 번의 저장이 **base 3 shard 를 읽어 어댑터를 머지하고 15GB 를 network volume 에 쓰는** 작업이고, 그것이 **`grad_accumulation_steps` 횟수만큼 반복**된다(methodology §4.3). 저장 조건이 배치 루프 안에 있어 `gradient_step_idx` 가 유지되는 16개 배치 동안 계속 참이 되기 때문이다.

여기서 나오는 실용 규칙:

- `save_steps` 를 작게 잡으면 저장이 학습 시간을 압도한다. 총 스텝의 1/5 같은 관례를 그대로 쓰면 안 되고, **저장 1회 실측치를 곱해 보고 정한다**
- `grad_accumulation_steps` 를 낮추면 저장 반복도 함께 줄어든다. 배치 조합 결정이 메모리뿐 아니라 저장 비용에도 걸린다
- `max_steps` 는 `save_steps` 의 배수여야 한다. 종료 조건이 저장 조건 뒤에 평가되므로 배수가 아니면 **마지막 학습 상태가 저장되지 않고 끝난다**

저장 1회 소요는 실행마다 **7-25분으로 변동**했다. 같은 조합·같은 GPU 인데도 그렇다. network volume 이 공유 파일시스템이라 쓰기 속도가 그때의 클러스터 상태에 좌우된다 — **클라우드 스토리지의 성능은 재현되는 값이 아니다**는 것이 이 측정에서 얻은 사실이다. 계획에는 보수적인 값을 쓴다.

### 2.3 로컬 대비 비용 판단

이 작업은 로컬 RTX 4070 12GB 로는 **불가능**하다(§1.1). 클라우드 1사이클 비용이 $1.18 이므로, 4-bit 학습 같은 비표준 경로로 로컬에 욱여넣어 얻는 절감액은 그 리스크를 정당화하지 못한다. 비표준 경로를 쓰면 이후 "성공률이 오르지 않았다" 의 원인 후보에 "4-bit 학습" 이 추가되고, 그것을 배제하려면 표준 경로로 한 번 더 학습해야 한다 — **결국 더 비싸진다.**

## 3. 학습 지표

원본: [`raw/loss_history.csv`](raw/loss_history.csv) (201 표본). 지표의 정의는 methodology §5.1.

| 스텝 | epoch | `train_loss` | action 정확도 | `l1_loss` |
|---|---|---|---|---|
| 0 | 0.0 | 10.7541 | 0.1161 | 0.41169 |
| 200 | 0.9 | 1.5870 | 0.5536 | 0.09769 |
| 400 | 1.7 | 1.5177 | 0.5536 | 0.07087 |
| 600 | 2.6 | 1.1750 | 0.6696 | 0.05714 |
| 800 | 3.4 | 0.9453 | 0.6964 | 0.05028 |
| 1000 | 4.3 | 0.5840 | 0.8304 | 0.02458 |
| 1200 | 5.1 | 0.5867 | 0.8304 | 0.02920 |
| 1400 | 6.0 | 0.4669 | 0.8571 | 0.01877 |
| 1600 | 6.8 | 0.4309 | 0.8214 | 0.01078 |
| 1800 | 7.7 | 0.3796 | 0.8482 | 0.02801 |
| 2000 | 8.5 | 0.3968 | 0.8661 | 0.02570 |

마지막 10 표본(스텝 1910-2000) 평균: `train_loss` **0.4311** / 정확도 **0.8464** / `l1_loss` **0.01741**

### 3.1 곡선이 말하는 것

- **1 epoch 이 되기 전에 대부분이 끝난다.** 10.75 -> 1.59 의 급감이 스텝 200 안에서 일어난다. 사전학습된 모델이 새 action 분포와 토큰 규칙에 맞춰지는 단계이며, 그 뒤는 완만하다
- **후반의 개선 폭이 작다.** 스텝 1000 이후 0.58 -> 0.40 이다. 스텝을 더 늘려 얻을 이득이 크지 않을 가능성이 있고, 반대로 8.5 epoch 이 과한지도 이 곡선만으로는 알 수 없다(§3.3)
- **정확도 0.87 은 토큰 일치율이다.** 로봇이 성공한 비율이 아니라, 이산화된 action 토큰을 정답과 같게 예측한 비율이다

### 3.2 loss 하락은 통과 기준이 아니다

이것이 이 절에서 가장 중요한 문장이다. **라벨이 일관되게 틀려 있어도 모델은 그 틀린 라벨을 잘 맞추게 되고 loss 는 똑같이 예쁘게 떨어진다.** loss 는 "모델이 주어진 정답에 가까워지고 있는가" 만 보고 정답 자체의 옳고 그름은 보지 않는다.

라벨의 정합성은 이 측정이 아니라 **데이터셋 구축 단계의 검증**이 담당한다. 그 검증은 별도로 통과했고, 이 측정에서도 간접 확인이 하나 있다 — [`raw/dataset_statistics.json`](raw/dataset_statistics.json) 의 `action.mean[6]` 이 **0.4319** 로, 데이터 생성 시점에 잰 gripper 의 "1 의 비율 0.432" 와 일치한다. 라벨이 빌드 -> 로더 -> 학습을 통과하며 변형되지 않았다는 뜻이다.

### 3.3 held-out 평가가 없다

학습 스크립트는 `train[:95%]` 만 사용하고 나머지 5% 로 검증하지 않는다. **표의 세 지표는 전부 학습 데이터에 대한 값이다.**

3,760 프레임을 8.5 epoch 돌았으므로 정확도 0.87 이 일반화인지 암기인지 이 측정으로는 구분되지 않는다. 데이터가 작을수록 이 구분이 중요해지고, 이 데이터셋은 작다.

**따라서 이 사이클의 성패는 여기서 확정되지 않는다.** 정책을 시뮬레이터에 연결해 성공률을 재는 것이 다음 단계이고, 그 수치가 zero-shot 기준선과 비교됐을 때 비로소 "학습이 유효했는가" 가 판정된다.

## 4. 인프라에서 배운 것

수치가 아니라 절차에 관한 발견이다. 클라우드 GPU 로 학습을 옮길 때 반복될 문제들이다.

### 4.1 회수 경로를 먼저 확보해야 한다

세 경로 중 하나만 동작했다(methodology §6.2).

| 경로 | 결과 |
|---|---|
| rsync over 프록시 SSH | 프록시가 원격 명령 실행을 거부해 불가 |
| `runpodctl` P2P | pod -> 로컬 방향에서 막힘. 반대 방향은 성공 |
| network volume 의 S3 API | 동작 |

**전송 도구의 성패가 방향에 따라 갈린다**는 것이 핵심이다. 데이터를 올릴 때 성공한 도구가 결과물을 내릴 때 실패한다. 그리고 이것은 **학습이 끝난 뒤에 발견된다** — 그때는 이미 요금이 흐르고 있고 산출물이 pod 안에 갇혀 있다.

S3 API 는 볼륨을 만들 때 **지원 데이터센터를 골라야** 쓸 수 있다. 즉 회수 경로의 확보 여부가 pod 을 띄우기도 전, 볼륨 생성 시점에 결정된다.

### 4.2 기본 경로에 남는 것은 사라진다

컨테이너 안(container disk)에 떨어지는 것들이 pod 정지·삭제와 함께 없어진다. 이번에 걸린 것 둘:

| 대상 | 기본 위치 | 조치 |
|---|---|---|
| LoRA 어댑터 | `adapter-tmp` (상대 경로) | `--adapter_tmp_dir` 로 volume 지정 |
| wandb 기록 (**loss 의 유일한 소재**) | `./wandb` | `WANDB_DIR` 로 volume 지정 |

두 번째가 특히 조용하다. loss 는 stdout 에 찍히지 않고 wandb 로만 가므로, `WANDB_MODE=offline` 만 설정하고 위치를 손대지 않으면 **학습은 성공하는데 지표가 통째로 사라진다.** 그 사실은 회수 후 `grep loss train.log` 가 0건을 낼 때 비로소 드러난다.

### 4.3 15GB 를 옮기지 않아도 된다

머지 가중치 = base + 어댑터이고, base 15GB 는 로컬에 이미 있다. **어댑터 462MB 만 받아 로컬에서 다시 합치면 같은 모델이 된다.** 회수 대상을 15GB 에서 수백 MB 로 줄이는 판단이며, 이것이 §4.1 의 좁은 전송 경로를 감당 가능하게 만들었다.

전제는 **base 리비전 일치**다. 어댑터가 자기 설정에 base 리비전을 기록하므로([`raw/adapter_config.json`](raw/adapter_config.json)) 로컬 캐시의 스냅샷 해시와 대조할 수 있고, 이 측정에서는 일치를 확인했다.

어댑터가 462MB 인 것은 `target_modules` 에 `lm_head` 가 포함되어 어휘 x 임베딩 차원 행렬이 함께 저장되기 때문이다. rank 32 어댑터만이라면 수십 MB 다.

## 5. 이 측정이 확정하지 못한 것

- **정책의 성공률.** 학습을 마쳤을 뿐 시뮬레이터에서 돌려 보지 않았다. "돌아간다" 와 "맞다" 는 다르다
- **일반화 여부.** held-out 평가가 없어 정확도 0.87 이 암기인지 구분되지 않는다 (§3.3)
- **재머지의 동일성.** 어댑터 + 로컬 base 재머지가 원본 머지 가중치와 같은 결과를 내는지 비교하지 않았다. 리비전과 버전 조합은 맞춰 두었다
- **최적 스텝 수.** 8.5 epoch 이 적정인지 과한지는 성공률을 재기 전에는 알 수 없다
- **배치 조합의 최적점.** VRAM 6GB 가 남았고 `batch 2 / accum 8` 을 시도하지 않았다 (§1.2)
- **저장 비용의 재현성.** 7-25분 변동의 원인을 클러스터 상태로 추정했을 뿐 분리해 재지 않았다
