# 성공률이 오르지 않았을 때 무엇을 주장할 수 있는가 — sim 에서 OpenVLA LoRA adaptation, 설계와 배제 분석

> 발행: 2026-08-31 · [physical-ai-study] 프로젝트의 v1.5 산출물. 측정 기록 원본: [`measurements/`](./measurements/) · 재현 절차: [`reproduce/`](./reproduce/)

## 1. 문제

VLA (Vision-Language-Action) 모델을 특정 task 에 adaptation 할 수 있는지 확인하고 싶었다. 대상은 OpenVLA 7B, task 는 ManiSkill 시뮬레이터의 PickCube (큐브를 집어 목표 지점에 놓기) 다.

왜 sim 인가. 두 가지 이유였다.

- **미학습 분포의 확보**: OpenVLA 의 사전학습 데이터 (Open X-Embodiment) 에 ManiSkill 렌더 화면은 없다. zero-shot 이 못 하는 것이 확실한 지점에서 시작해야 adaptation 의 효과를 잴 수 있다.
- **타이밍**: 실기 로봇 팔이 준비되기 전에 데이터 수집-학습-평가 파이프라인 전체를 한 번 완주해 두려 했다.

이 선택의 한계도 처음부터 명확했다. sim 에서의 adaptation 증거는 real 로봇에서의 증거와 설득력이 다르다. 이 글의 결과는 전부 sim 안의 이야기이고, real 확장은 다음 단계다 (§6).

## 2. 설계 — 무엇을 통제했는가

**변인은 모델 하나다.** zero-shot (openvla-7b + bridge_orig 통계) 과 fine-tuned (LoRA 머지 가중치 + 자체 데이터셋 통계) 를 같은 환경, 같은 seed 목록 (0-99), 같은 step 예산 (200 env step, action repeat 4), 같은 양자화 (nf4 + double quant + fp16 compute), 같은 instruction 으로 평가했다. 두 결과 파일의 메타를 코드로 대조해 차이가 `model`, `unnorm_key` 두 항목뿐임을 분석 전에 확인했다.

**지표는 두 층이다.** 최종 성공률 (placed) 하나만 보면 0 대 0 으로 끝났을 때 아무것도 말할 수 없다. 그래서 episode 를 4단계 (reached / grasped / lifted / placed) 로 쪼개 부분 도달률을 함께 쟀다. 단, 두 지표는 다른 것이다 — 부분 도달률의 개선을 성공률의 개선으로 바꿔 말하지 않는 것을 보고 규칙으로 먼저 정했다.

**N 과 통계 방법을 결과 전에 정했다.** N=100 은 스텝당 실측 시간 (310.8 ms) 에서 역산해 "반폭 약 10%p 해상도, 두 모델 합계 약 52분" 으로 정한 값이다. 구간은 Wilson score (0/N 에서도 상한이 0 이 되지 않는 방법), 짝지은 비교는 같은 seed 끼리 묶은 exact McNemar (불일치 쌍 이항검정, 양측, alpha 0.05) 로, 결과를 보기 전에 문서로 고정했다. 결과를 본 뒤 방법을 고르면 그것은 분석이 아니라 사후 정당화가 되기 때문이다.

무행동 하한도 미리 쟀다. seed 0-99 에 zero action 만 넣는 probe 를 돌리면 seed 8 과 58 이 초기 배치만으로 성공한다 (목표 지점이 큐브 바로 옆에 떨어지는 degenerate 배치). 이 두 seed 의 성공은 조작 성공으로 세지 않고, 구간 추정은 이를 제외한 98쌍 기준으로 했다.

## 3. 실행 — 각 단계에서 무엇을 검증했는가

이 파이프라인에서 가장 시간을 쓴 것은 학습이 아니라 검증이다. "돌아간다" 와 "맞다" 는 다르고, 각 단계의 검증이 마지막 주의 원인 분석 (§5) 의 재료가 된다.

**하네스 검증 (측정 장치의 상한 대조).** 성공률을 재기 전에, 정답 좌표를 아는 scripted 해법을 같은 측정 장치에 넣어 20/20 성공을 확인했다. 소비 step 은 최대 49 로 예산 200 의 약 1/4 — 이후 실패를 "시간 부족" 으로 설명할 수 없게 만드는 수치다. 원래는 ManiSkill 동봉 motion planning 해법을 쓰려 했으나 mplib 바이너리가 numpy 2 와의 ABI 불일치로 세그폴트를 내서, 같은 제어 모드를 쓰는 scripted 해법을 직접 작성했다 — 결과적으로 정규화 action 경로까지 함께 검증됐다.

**라벨 round-trip.** 처음에는 "실제로 이동한 거리" 를 라벨로 썼다가 되돌렸다. PD 컨트롤러의 추종률이 평균 0.42 라, 실제 이동량을 라벨로 쓰면 재생 시 42% 가 한 번 더 곱해져 위치 오차 mean 0.082 m — 기준 (max 0.001 m) 의 100배로 실패했다. 라벨을 "expert 가 명령한 델타" 로 재정의한 뒤 왕복 항등 최대 오차 1.49e-8 (float32 유효자리 한계), week0 계약 표 실측 6/6 일치로 통과했다. 정직하게 남길 것: 재정의 후의 sim 재생 검증 (강한 기준) 은 기록상 미측정으로 남아 있고, §5 의 잔여 후보에 그대로 올라가 있다.

**로드 검증 / 정규화 계약.** 학습 파이프라인이 내 데이터를 실제로 읽는지, 그리고 정규화가 한 번만 걸리는지를 코드와 실측으로 확인했다. 통계 파일의 규모 (100 trajectories / 3,760 transitions) 가 라벨 원본과 일치하고, 통계값이 물리 단위 (위치 ±0.015 m) 라 사전 정규화가 없었음이 확인된다. gripper 부호 규약 (0=닫힘) 도 로더 규약과 대조해 일치를 확인했다 — 이 차원은 정규화에서 제외되어 틀려도 loss 는 예쁘게 내려가기 때문에, 여기가 값싸게 잡을 수 있는 마지막 지점이었다.

**학습 완주와 4층 모델 검증.** RTX 4090 24GB pod 에서 LoRA (rank 32) 2,000 스텝 (8.5 epoch) 을 94분, 약 $1.18 로 완주했다. train_loss 10.75 -> 0.40, action token 정확도 0.12 -> 0.87. 단 이 곡선은 라벨이 일관되게 틀려 있어도 똑같이 나오므로 통과 기준이 아니라 "학습이 돌았음" 의 기록이다. 이후 로컬에서 재머지 (색인 total_size 와 텐서 이름 집합이 pod 머지와 일치), 4bit NF4 적재 (VRAM 4.38 GB, 가중치 경고 0건), 결정성 (같은 입력 3회 추론 bit 동일), unnorm_key 대역 검사 (출력 위치 델타가 자체 통계 대역 ±0.012 안, bridge_orig 대역 ±0.029-0.042 와 구분) 의 4층을 통과시켰다.

**측정 조건 무결성.** 평가 하네스는 실행마다 메타 (모델 경로, unnorm_key, 양자화 설정, seed 규칙, commit) 를 결과 파일 첫 줄에 기록한다. 분석 직전에 두 파일의 메타를 다시 대조해 차이가 2항목 (model, unnorm_key) 뿐임을 확인하고 시작했다.

## 4. 결과

| 단계 | zero-shot | fine-tuned | 불일치 쌍 (개선/악화) |
|---|---|---|---|
| reached (큐브 5 cm 이내 접근) | 0/98 | 92/98 | 92 (92/0) |
| grasped (파지) | 0/98 | 75/98 | 75 (75/0) |
| lifted (4 cm 이상 들어올림) | 0/98 | 1/98 | 1 (1/0) |
| **placed (최종 성공)** | **0/98** | **0/98** | **0** |

- placed: 양쪽 모두 조작 성공 0/98, 95% Wilson 구간 [0%, 3.8%]. 100쌍 원값은 2/100 인데 그 2건은 양쪽 모두 무행동 seed {8, 58} 그 자체다.
- 짝지은 비교: placed 의 불일치 쌍이 0 이므로 검정 자체가 성립하지 않는다. 판정은 "판정 불가 (불일치 쌍 0)" — 이것은 "차이 없음" 과 다른 진술이다. 이 N 으로는 차이에 대한 정보가 없다는 뜻이다.
- 단계별 지표는 기술 통계만 보고한다 (다중 비교를 피하기 위해 구간·검정은 1차 지표에만 붙이기로 사전에 정했다).
- 원시 집계: [`measurements/openvla-lora-eval/raw/`](./measurements/openvla-lora-eval/raw/) (episode 별 jsonl 2개 + 실행 로그 2개), 집계 스크립트: [`analyze_results.py`](./measurements/openvla-lora-eval/scripts/analyze_results.py), 단계 집계 그림: [`stage_counts.png`](./measurements/openvla-lora-eval/plots/stage_counts.png)

요약하면: fine-tuned 모델은 접근 (92/98) 과 파지 (75/98) 까지는 도달하게 됐지만, 파지한 74건이 들어올리기로 이어지지 않았고 최종 성공은 0 이다. zero-shot 은 접근조차 0/98 이었다.

## 5. 분석 — 무엇이 배제되고 무엇이 남았는가

"성공률이 안 올랐다" 앞에서 "데이터가 적어서 / 분포가 달라서" 를 나열하는 것은 분석이 아니다 — 그 문장들은 결과를 보지 않고도 쓸 수 있다. 대신 앞 단계들의 검증 기록이 원인 후보를 실제로 배제한다.

**배제된 후보** (각 행의 근거는 파일과 판정 수치로 남아 있다):

| 배제된 후보 | 근거 (판정) |
|---|---|
| 측정 장치 고장 (환경·루프·판정·step 예산) | scripted 상한 대조 20/20, 최대 49/200 step |
| 라벨 변환의 수치 손실·규약 불일치 | 왕복 항등 1.49e-8, 계약 표 실측 6/6, gripper 규약 일치 |
| 회전 표현 불일치 (axis-angle vs euler) | 로더의 EEF_POS 인코딩과 라벨 구성 일치 확정 |
| 데이터가 학습에 안 들어감 | 통계 파일 100/3,760 이 라벨 원본과 일치 + 학습 정확도 0.12 -> 0.87 |
| 라벨 이중 정규화 | 통계 실측이 물리 단위 (±0.015 m) |
| 학습이 안 돌았음 | 2,000 스텝 완주, loss 10.75 -> 0.40 |
| 체크포인트 손상·재머지 오류 | 색인 일치 + 가중치 경고 0건 + 결정성 bit 동일 |
| unnorm_key 오연결 | 출력 대역이 자체 통계 대역과 일치, 두 키 대역 구분 |
| 양자화 조건 차이 | 두 실행 메타의 quant 필드 동일 (nf4+dq+fp16) |
| 측정 조건 누출 | 메타 차이 2항목 (model, unnorm_key), seed 목록 일치 |

**남은 후보** (배제하지 못했으므로 남긴다):

| 남은 후보 | 왜 남는가 | 가르려면 |
|---|---|---|
| 데이터 규모 (100 ep / 3,760 transition) | 최소선 이상을 시도하지 않았다 | 규모를 늘린 2차 학습 |
| 상태 분포 협소 (expert-only) | 이탈 상태의 정답이 데이터에 없다 | DAgger 류 이탈 상태 라벨링 |
| 도메인 갭 | 이번 실험의 전제였다 | 도메인 정합 환경 또는 real 데이터 |
| 학습 스텝·하이퍼파라미터 | 예산 역산 값, 탐색 없음 | 탐색 실험 |
| task 난이도 | PickCube 하나로 고정 | 다른 task |
| 학습의 무작위성 | 학습 1회, seed 반복 없음 | 반복 학습 |
| 라벨 재생 무결성 (강한 기준) | 재생 검증이 기록상 미측정 | 재생 스크립트 재실행 |

grasp 이후에 실패가 몰린 패턴 (75건 파지, 1건 lift) 은 "이탈 상태에서의 회복 능력 부재" 나 "파지 이후 구간의 라벨 품질" 쪽 후보와 양립하지만, 성공 관측이 0 이라 이 데이터만으로 남은 후보들의 우선순위를 정할 수는 없다. 패턴의 해석은 가설이지 판정이 아니다.

"무엇이 원인인지 모른다" 와 "무엇이 원인이 아닌지는 안다" 는 완전히 다른 진술이다. 이 실험이 산출한 것은 후자이고, 위 두 표가 이 프로젝트의 핵심 산출물이다.

## 6. 한계와 다음

- **sim 증거의 한계**: 이 결과는 PickCube-v1, 단일 embodiment, 학습 1회, N=100 조건 안의 이야기다. real 로봇 성능, 다른 task, "LoRA 는 원래 이렇다" 류의 일반화는 이 데이터가 지탱하지 않는다.
- **모델 세대**: OpenVLA 를 고른 시점 (2026.06) 과 이 글을 마감하는 시점 사이에 필드가 한 세대 넘어갔다 — π0.7, Gemini Robotics 2, GR00T N1.7 이 나왔고, 공개 모델의 베이스라인은 action-chunk 계열 (SmolVLA, π0.5, GR00T) 로 이동했다. OpenVLA 의 자기회귀 토큰 생성이 만드는 300 ms 급 추론 시간도 chunk 계열에서는 구조적으로 해소된다. 그래서 다음 단계는 모델을 다시 고르는 일이 아니라, 여기서 확립한 eval 논리 (사전 등록한 N·구간·짝지은 비교, 부분 도달률, 배제 분석) 에 새 세대 모델을 — 이번에는 실기에서 — 넣는 것이다.
- **real 확장**: 다음 단계는 이 파이프라인 (수집 -> RLDS -> LoRA -> 재머지 -> 4층 검증 -> N회 측정) 을 자작 로봇 팔의 teleop 데이터로 옮기는 것이다. real 로 옮기는 순간 위의 배제 목록은 리셋된다 — 그때 §5 의 표가 "무엇을 다시 검증해야 하는가" 의 목록으로 재사용된다.
- **남은 후보를 가르는 순서**: 비용 기준으로 라벨 재생 무결성 재실행 (분 단위) -> 파지 이후 로그 분석 (시간 단위) -> 반복 학습·규모 확장 (달러 단위) 순이 합리적이다.
